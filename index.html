What are Code Standards?

Core Fundamentals

Code standards are a set of unified rules and formatting guidelines that developers follow to keep a codebase consistent, readable, maintainable, scalable, less error-prone, and team-friendly.

❌ Without Standards 
const username="Stuti"
function getuser(){
return username
}
✅ With Standards 
const username = "Stuti";

function getUser() {
  return username;
}
2

Why Do We Need Code Standards?

Team Collaboration

Imagine a team of 10 developers writing code differently (e.g., getUser(), GetUser(), get_user(), getuser()). It quickly becomes chaotic. Unified standards ensure harmony across the team.

Benefit Impact & Meaning
Readability Code is instantly understandable by any engineer on the team.
Maintainability Refactoring, updating, or fixing bugs takes significantly less time.
Consistency Every file looks like it was written by a single, cohesive author.
Fewer Bugs Eliminates common syntax pitfalls and scope bugs.
Collaboration Smooth onboarding for new devs and faster code review turnaround.
Scalability Large enterprise projects remain clean as features multiply.

Naming Conventions

Code Style

Consistent casing rules make code self-documenting. Use camelCase for variables and functions, and UPPER_SNAKE_CASE for fixed configuration constants.

❌ Avoid Inconsistent Casing 
const first_name = "Stuti";
const userage = 22;
const TOTALAMOUNT = 500;
✅ Recommended Standard 
const firstName = "Stuti";
const userAge = 22;

// Action-verb functions:
function getUser() {}
function calculateTotal() {}

// Fixed global configuration constant:
const MAX_RETRY_COUNT = 3;
4

Use Meaningful Names

Clean Code

Names should immediately explain what the variable or function represents without needing extra comments.

❌ Cryptic Single-Letter Names 
const x = 500;
const d = 10;
const u = getUser();
✅ Self-Descriptive Names 
const totalAmount = 500;
const discount = 10;
const user = getUser();
5

Avoid Magic Numbers

Readability

A magic number is a raw number in code without explanation. Replace magic numbers with named constants to express intent clearly.

❌ Unclear Magic Number 
if (retryCount > 3) {
  // What does 3 represent?
}
✅ Named Constant 
const MAX_RETRIES = 3;

if (retryCount > MAX_RETRIES) {
  // Intention is 100% explicit
}
6

Use const and let Correctly

Scope & Safety

Default to const for all variable declarations. Use let only when re-assignment is explicitly needed. Completely avoid var in modern JS.

❌ Outdated var 
var name = "Stuti"; // Leaks scope
✅ Block-scoped const / let 
const userName = "Stuti"; // Default
let count = 0;            // Only if reassigned
count++;
7

Keep Functions Small (Single Responsibility)

Architecture

A function should do one thing well (Single Responsibility Principle — SRP). Break monolithic functions into small, reusable helpers.

❌ Monolithic Function (Does Everything) 
function processUser() {
  // validate user
  // calculate salary
  // save to database
  // send email
  // log activity
}
✅ Modular Focused Helpers 
function validateUser() {}
function calculateSalary() {}
function saveUser() {}

function processUser() {
  validateUser();
  calculateSalary();
  saveUser();
}
8

Avoid Duplicate Code — DRY

Principles

DRY (Don't Repeat Yourself). Extract repetitive calculation logic into a single function so changes only ever need to happen in one place.

❌ Repetitive Logic 
const user1Total = price1 + tax;
const user2Total = price2 + tax;
const user3Total = price3 + tax;
✅ Encapsulated Function 
function calculateTotal(price, tax) {
  return price + tax;
}

const user1Total = calculateTotal(price1, tax);
const user2Total = calculateTotal(price2, tax);
9

Don't Overuse Comments

Documentation

Comments should explain why complex business decisions were made, not restate the obvious code behavior (the what).

❌ Restating Obvious Code 
// Increment count by 1
count++;

// Call API
callApi();
✅ Explaining Rationale & Context 
// Payment gateway rate-limits on burst attempts, retry once after 500ms
retryCount++;
10

Use Strict Equality (===)

Type Safety

Always use === and !== instead of == and != to prevent unintended implicit type coercion bugs.

❌ Loose Equality (Implicit Coercion) 
5 == "5" // true! Dangerous implicit coercion
✅ Strict Equality 
5 === "5" // false! Checks value AND type

if (userId === 10) {
  // Type-safe comparison
}
11

Avoid Deeply Nested Code (Guard Clauses)

Readability

Replace deeply nested if blocks with early return guard clauses to flatten logic and lower cognitive load.

❌ Deep Nesting (Pyramid of Doom) 
if (user) {
  if (user.isActive) {
    if (user.hasPermission) {
      if (user.role === "admin") {
        // do work
      }
    }
  }
}
✅ Clean Guard Clauses 
if (!user) return;
if (!user.isActive) return;
if (!user.hasPermission) return;
if (user.role !== "admin") return;

// do work cleanly
12

Use Optional Chaining (?.)

Modern JS

Safely access deeply nested object properties without verbose multi-level checking using ?. syntax.

❌ Verbose Guard Checks 
if (user && user.address && user.address.city) {
  console.log(user.address.city);
}
✅ Concise Optional Chaining 
console.log(user?.address?.city);
13

Use Nullish Coalescing (??)

Modern JS

Use ?? to fallback only when values are null or undefined. Unlike ||, it preserves valid falsy values like 0, false, and "".

❌ Over-eager OR Operator (||) 
const name = user.name || "Guest";
// Erroneously falls back if user.name is ""
✅ Safe Nullish Coalescing (??) 
const name = user.name ?? "Guest";
// Falls back ONLY if null or undefined
14

Prefer Modern Array Methods

Functional Style

Replace imperative for loops with declarative higher-order array functions like map, filter, find, and reduce.

❌ Imperative Loop 
const names = [];
for (const user of users) {
  names.push(user.name);
}
✅ Declarative map() 
const names = users.map(user => user.name);
15

Don't Mutate Data Unnecessarily

State Integrity

Avoid directly modifying objects and arrays in place. Use spread syntax (...) to create immutable state updates, essential for React/Redux stability.

❌ Direct Object Mutation 
user.name = "John"; // Mutates reference
✅ Immutable Copy 
const updatedUser = {
  ...user,
  name: "John"
};
16

Handle Errors Properly

Reliability

Never leave an empty catch block. Swallowing exceptions makes debugging nearly impossible in production environments.

❌ Empty Catch (Swallowed Error) 
try {
  await fetchData();
} catch (error) {
  // Swallowed! Silent failure!
}
✅ Handled & Logged Exception 
try {
  await fetchData();
} catch (error) {
  console.error("Failed to fetch user:", error);
}
17

Use async/await for Asynchronous Code

Async Patterns

async/await flattens promise chains, making asynchronous flows look and behave sequentially like synchronous code.

❌ Nested Promise Chains (.then) 
getUser()
  .then(user => getOrders(user.id))
  .then(orders => processOrders(orders))
  .catch(error => console.error(error));
✅ Readable async/await 
try {
  const user = await getUser();
  const orders = await getOrders(user.id);
  processOrders(orders);
} catch (error) {
  console.error(error);
}
18

Avoid Hardcoding Configuration

Configuration

Keep environment-dependent values (API endpoints, thresholds) in environment variables or configuration objects.

❌ Hardcoded Production Endpoint 
fetch("https://production-api.example.com/users");
✅ Environment-based Config 
const API_BASE_URL = process.env.API_BASE_URL;

fetch(`${API_BASE_URL}/users`);

Separate Concerns

Architecture

Divide applications into logical modules (UI components, services, utilities, API hooks) so each layer focuses purely on its own domain.

src/
├── components/   # View & UI layout
├── services/     # Data fetching & network logic
├── utils/        # Helper utility functions
└── constants/    # Fixed configuration
20

Avoid Unnecessary Complexity

Clean Code

Readable code is always superior to overly dense, "clever" one-liners that confuse teammates.

❌ Dense "Clever" One-Liner 
const res = users?.filter(Boolean)?.map(u => u?.name)?.filter(Boolean);
✅ Clear Multi-step Logic 
const validUsers = users.filter(Boolean);
const names = validUsers.map(user => user.name);

Don't Create Abstractions Too Early

Architecture

Avoid constructing complex abstract classes and factories for single-use cases based on hypothetical future needs.

Tooling

Tool Primary Job Enforced Rules Examples

Code Review Best Practices

Team Process

When reviewing pull requests, systematically evaluate five pillars:

  • Readability: Can I understand this logic in under 60 seconds?
  • Logic & Edge Cases: Are null/undefined values and error paths covered?
  • Security: Are inputs sanitized? Are tokens or credentials safe?
  • Performance: Are heavy functions avoided inside render loops or standard iterations?
  • Testing: Are unit tests verifying the critical business outcomes?
25

Don't Commit Secrets

Security

Never hardcode API credentials, passwords, or secret tokens inside repository code files.

❌ Hardcoded Secret Token 
const API_KEY = "abc123secret";
✅ Environment Variable 
const API_KEY = process.env.API_KEY;
26

Write Testable Code

Testing

Small, pure functions without side effects are straightforward to test independently with automated test runners like Jest or Vitest.

Core Software Principles: KISS & YAGNI

Core Mindset

KISS

Keep It Simple, Stupid. Prioritize clean, straightforward code over complex or overly clever shortcuts.

YAGNI

You Aren't Gonna Need It. Don't write code or configuration systems for hypothetical future requirements.
